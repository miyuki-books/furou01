多くのプログラマーにとって、テストは「書かなければ」という義務で始まる。しかし実際に書き始めるとぶつかるのが設計の問題だ。何をテストするのか、どこまで細かく書くのか、モックはどう使うのか。これらは経験則や職場の習慣で済ませている人がほとんどだ。テストそのものの設計を、原則から学び直す本を紹介する。

## テスト第一の考え方を理解するなら

ケント・ベック『テスト駆動開発』は、テストを書く目的を文字通り「赤・緑・リファクタ」のサイクルに還元している。単なるテクニック集ではなく、テストを先に書くことで設計がどう変わるかという実装の流れを、具体的な例で示す。本書は2002年出版の古い本だが、この本がなければ現在のテスト駆動開発という実践は存在しない。

本書は短く、読みやすい。ただし Java で書かれた具体例が多いため、動的言語や型チェックが異なる言語を使っている人には、直接持ち込める例が限られる点には注意する必要がある。

## ユニットテストのアンチパターンを避けるなら

ウラジミール・ホリコフ『単体テストの本質』は、ユニットテストで「やってしまいがち」な設計的な誤りを体系化している。何をモックするべきか、テストは何を検証すべきか、テストコードは何に依存すべきではないか。こうした判断基準が、原則として説明される。

本書は2020年出版で、モダンな C# で書かれている。設計パターンの説明では Java の例も混ざるが、言語を問わず読める内容だ。テストの「なぜ」を言語化したいなら、この一冊を読むことで仕事のテストコード見直しのやり方が大きく変わる。

## テスト技法そのものを深掘りするなら

ジェラード・メザロス『xUnit テスト・パターン』は、テストコードの書き方を68のパターンに分類し、それぞれの適用場面と落とし穴を説明している。テストフィクスチャ、スタブ、モック、プライベート・メソッドのテスト方法など、実装で直面するほぼすべての状況が網羅されている。

2007年出版で、内容は Java/C#/C++ を想定しているため、その後に出たテストフレームワークの細部は古い。ただし考え方の部分は普遍的だ。辞書的に使う本で、必要な場面で引く使い方が想定されている。

## 選ぶ順序

テスト駆動開発の思想を初めて学ぶならベックから。既にテストを書いているが品質に不安があるならホリコフから。テスト技法の深い説明が必要なら、メザロスを手元に置く。どれ一つとして他を完全に代替しない—それぞれ異なる層の知識を扱っているからだ。
