## インフラ構築の課題：手作業の限界

サーバー設定や環境構築を手作業で進めると、以下の問題が生じます。

- 設定内容が属人化し、担当者の退職や移動で知識が失われる
- 同じ環境を再現しようとしても、微妙な違いが発生する
- 本番環境での手作業変更が、構成管理外になり、後のコード化時にズレが生じる
- スケーリングやロールバックが手動作業になり、ミスと工数が増える

Infrastructure as Code（IaC）はこれらの問題に対する標準的なアプローチです。テキストベースの設定ファイルでインフラを定義し、バージョン管理・自動デプロイ・レビュープロセスを適用する手法です。

ただし、IaCの学習には複数の層があります。「原則と実装パターンを知ること」「特定ツール（TerraformやAWS CDK）の使い方」「組織への導入」——どこから始めるかで選ぶ本が変わります。

## 3冊の位置付け

### 1. 『[Infrastructure as Code : クラウドにおけるサーバ管理の原則とプラクティス](/go/9784873117966)』

IaCの概念、歴史、設計原則をカバーする基礎本です。著者Kief Morrisは、この分野の有名な実践家で、本書は単なるツール解説ではなく「なぜIaCが必要か」から始まります。

**特徴：**

- クラウド時代のインフラ管理が直面する課題を体系的に説明
- 「不可変インフラ」「構成ドリフト」などの概念を詳しく解説
- ツール非依存の原則が主で、具体的な実装は補足レベル
- 2017年版と古めだが、基礎的な考え方は今でも通用

**向いている人：** 

IaCの目的や考え方を理解した上で、組織に導入したい管理層や、複数のツール選択肢を評価したい立場の人。ツールを使い始める前に「なぜこれをするのか」を押さえたい学習者。

### 2. 『［詳解］AWS Infrastructure as Code――使って比べるTerraform＆AWS CDK』

AWS環境でのIaCを実装する2つの主流ツール（Terraform と AWS CDK）を、具体的なコード例で比較解説します。

**特徴：**

- 同じインフラを両ツールで実装し、差異を明確にしている
- TerraformはHCL、AWS CDKはPython/TypeScript/Go での書き方を全て網羅
- AWS固有のリソース（VPC、セキュリティグループ、Lambda等）を題材に実践的
- 「どちらを選ぶか」の判断基準も示唆される

**向いている人：**

AWSを使う組織で、TerraformかAWS CDKか選択を迫られている開発チーム。両者の違いを実際のコードレベルで理解したい実装者。

### 3. 『詳解Terraform : Infrastructure as Codeを実現する』

Terraformに特化した実装ガイドです。状態管理、モジュール設計、複数環境管理など、Terraformを本番運用で使う際の実践的な課題をカバーします。

**特徴：**

- Terraformの基礎から応用まで段階的に学習可能
- リモート状態管理（S3 + DynamoDB等）の設定方法を詳しく説明
- モジュール設計のベストプラクティスを示唆
- 複数環境（開発・ステージング・本番）の管理パターンを解説

**向いている人：**

Terraformを本格的に組織導入し、単なる構文レベルではなく、運用体系を構築したいチーム。状態ファイルの管理やモジュール化で困っている開発者。

## 学習順序のガイド

### パターン1：原則から学びたい場合

1冊目：『Infrastructure as Code の原則とプラクティス』で IaC の必要性と設計思想を理解
→ 2冊目：『詳解Terraform』でツール使用法を習得
→ 3冊目：『AWS Infrastructure as Code』で他のアプローチを参考に

### パターン2：即実装したい場合（AWS環境）

1冊目：『詳解Terraform : Infrastructure as Codeを実現する』の基礎章で構文を押さえる
→ 2冊目：『AWS Infrastructure as Code』で実装パターンを確認
→ 3冊目：『Infrastructure as Code の原則とプラクティス』で設計判断の背景を理解

### パターン3：ツール選択から始めたい場合

1冊目：『AWS Infrastructure as Code』で Terraform と AWS CDK の違いを理解
→ 組織で採用ツールを決定
→ 2冊目・3冊目：選んだツールの本と原則本で深掘り

IaCの導入は、ツール以前に「なぜ必要か」の理解と「どう運用するか」の設計が成否を分けます。3冊を補完的に活用することで、単なるツール使いではなく、インフラ運用の体系を構築できます。
