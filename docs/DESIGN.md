# 自律AI社員 実験計画 v2（確定版）

策定日：2026-08-09 ／ 実験期間：稼働開始から90日

このドキュメントは「なぜそう決めたか」の記録です。運用ルールは [`../CLAUDE.md`](../CLAUDE.md) を見てください。

---

## 1. 検証対象

**測る**：AI社員が90日間、計画外の人間介入をほぼ受けずに「観測 → 仮説 → 変更 → 再観測」を回し続けられるか。

**測らない**：月50,000円という金額。市場側の変数に支配され、設計の巧拙をほとんど測定できないため、判定から除外した。

### 主判定

| # | 指標 | 位置づけ |
|---|---|---|
| 1 | 計画外介入の回数（エラー対応・記事の修正削除・停止からの復旧） | **本体** |
| 2 | 定型消化の回数（週1回の note 投稿ボタン。90日で約13回が基準線） | 別枠 |
| 3 | 規約違反・事実誤認による削除率 | 品質 |
| 4 | 自己改善サイクルが出力を変えた回数（`state/decisions.jsonl` の行数） | ループの生存 |

### ボーナス判定

アフィリエイト報酬が1件でも発生したか（バイナリ）。**着金ではなく成果発生をもって達成**とする。
楽天の報酬確定は成果発生の翌々月10日で、着金を待つと90日に収まらないため。

## 2. 主体と費用

- 表示名は完全別のハンドルネーム。実体（ASP登録・受取口座・確定申告）は個人。
- 検証中は法人の Team Standard シートで実行。**初入金が発生した時点で個人契約へ移管**する。
- 追加課金は原則ゼロ。**例外は X API の従量課金のみ**（1投稿 $0.01、1日1投稿で月約 $0.3）。

## 3. 構成

```
自前ブログ（母艦・完全自動）
  ├─ 楽天アフィリエイトリンク → /go/:id → クリック計測 → /stats.json
  ├─ X 公式API（記事公開のたび自動投稿・無人）
  └─ note（週1・要約と導線のみ・人間がボタン3つ）
```

### なぜ自前ブログが母艦か

1. アフィリエイト審査に通る「メディア」の実体になる
2. プラットフォームの気まぐれで全消失しない
3. AI社員がファイルを書いて push するだけで完結し、SNS API の規約リスクを負わない

### なぜ楽天先行で、Amazon は後回しか

Amazon アソシエイトは**サインアップから180日以内に適格販売3件**が無いと本審査に進めずアカウントが閉じられる。
一方この実験はコールドスタートで、最初の2〜3ヶ月はほぼ読まれない前提を置いた。
登録した瞬間にタイマーが走るので、PVが立ってから人間が判断して登録する。
楽天は審査を挟まないため、無風でも失うものがない。

### なぜ note は週1手動か

note に公式APIは存在しない（[公式ヘルプ](https://www.help-note.com/hc/ja/articles/46643492548121)）。
非公式APIやブラウザ自動操作は規約違反のリスクがあり、条件「合法であること」に反する。
さらに `CLAUDE_CODE_OAUTH_TOKEN` による無人実行では claude.ai のコネクタが使えないため、
Chrome 操作は**そもそも技術的に無人では動かない**。

### なぜ note は要約のみか

note は canonical を設定できない。全文転載すると重複コンテンツになり、本家ブログが検索から消える。

### なぜ A8.net 等の高単価ASPを使わないか

単価ではなく期待値で見ると逆転するため。楽天/Amazon はリンク経由で**何を買っても**成果になるが、
A8の高単価案件は**特定の申込・購入のみ**が成果条件になる。月間PV 100 の仮定では、
前者が月0.1件程度に対し、後者は1件出るのに200ヶ月かかる計算になる。
「1円でも発生したか」をバイナリ判定に置いた以上、単価より発生確率が効く。

## 4. コンテンツ

- ジャンル外枠：技術書・ビジネス書（人間が固定、AI社員は変更不可）
- 型：**選書ガイド / 比較記事**（書評ではない。AI社員は本を読んでいない）
- 頻度：1日1本
- **AI生成である旨の記事内表示は入れない**。代わりに担保を2箇所へ移した。
  1. 体験詐称表現をコードで検出してブロック
  2. プロフィールページに一度だけ運営方針を記載
- PR表記は必須（景表法第5条第3号）

「AIっぽさを消す」は**文体の質向上に限定**し、人間の一次体験の偽装はしない。

## 5. 自律の境界

**AI社員が決める**：テーマ選定、訴求、タイトル、A/Bの打ち方

**人間が固定する**：禁止事項、予算、ジャンル外枠

**意図的に自律を切る**：
- Amazon アソシエイトの登録判断
- ジャンル追加（累計クリック30件または月間PV 500 到達で通知 → 人間が承認）
- 凍結後の復旧（ban evasion は規約違反）

> 自律性は「何をやるか」ではなく「どう改善するか」に置く。
> 目的関数を「利益」だけにすると、規約違反やスパムが最短経路になる。

## 6. ガードレール

**プロンプトではなくコードで強制する。** プロンプトの指示は確率的に破られる。

`scripts/check.mjs` が `exit 1` でブロックする条件：

1. PR表記の欠落
2. 体験詐称表現の検出
3. 許可リスト外ドメインへのリンク
4. 表・コードブロックの混入（note用出力）
5. AI臭スコアの閾値超過

## 7. 稼働

- 実行基盤：**GitHub Actions**
- 認証：`claude setup-token` で発行した1年有効の OAuth トークンを `CLAUDE_CODE_OAUTH_TOKEN` に設定
- 日次：記事生成（Haiku）
- 週次：振り返りと戦略更新（Sonnet）＋ note投稿キット生成

### なぜ PC のタスクスケジューラではないか

当初は PC で始める予定だったが、サブスク認証のヘッドレス実行が公式にサポートされていることが
確認できたため変更した（[公式ドキュメント](https://code.claude.com/docs/en/authentication)）。

主判定の第1指標が「計画外介入の回数」である以上、**PCのスリープや Windows Update で止まって
手動で起こすたびに指標が汚れる**。90日という長さでは、この差が効く。

### 停止条件

1. 連続3回の実行失敗
2. 週次トークン上限の残量が閾値以下
3. 凍結・提携解除の検知
4. 90日経過
5. 同じ記事で `check.mjs` が3回連続ブロック

## 8-2. クリック計測の精度（実測）

`/stats.json` の数字は**下限値**として読むこと。正確な実数ではない。

疎通確認で分かったこと。

- 当初の「カウンタを読んで+1して書く」方式は、**3クリックが1件**になった。
  KV が結果整合性なので、同時アクセスが揃って古い値を読み、同じ数字を書き戻す。
- 1クリック1キー方式に変更したところ、**5件同時で4件**まで改善した。
  集計値は KV の実キー数と一致しており、集計ロジック側の誤りではない。
- 残る1件の欠落は KV への書き込み失敗。リトライを1回入れたが、完全ではない。

実運用では同一ミリ秒に複数クリックが来ることはまずないので、実害は小さい。
ただし**「クリックが増えた/減った」を根拠に操作変数を動かすときは、この誤差幅を前提にすること。**
そもそも月間PVが数十の段階では統計的な有意差は出ないので、
ここを厳密にしても実験の主判定（自律性）には効かない。

## 9. 残る既知のリスク

1. **週次トークン上限の枯渇＝実験停止。** Standard シートは Pro の1.25倍しかない。最大の物理制約。
2. **90日間ゼロ入金が既定路線。** note と X を足してもコールドスタートは構造的に解けない。
3. **検索エンジンがAI生成コンテンツを評価しない可能性。** 1日1本なら大量生成には当たりにくいが、実質的価値がなければ順位は付かない。
4. **note の一次規約が未確認。** `terms.help-note.com` が 403 を返し本文を取得できていない。導線のみ・週1・手動なので現状の判断はクリーンだが、確認は残っている。
5. **楽天が「AI生成コンテンツ」を明文で禁じていないことは、黙認の保証ではない。**
6. **初入金が発生した日に、法人 → 個人の契約移管を即処理する必要がある。**

## 10. 撤退

累計コスト上限または90日、どちらか先に到達した時点で強制停止し、総括する。
**「安定して利益が出るまで動き続ける」は、裏返すと永久に赤字を垂れ流す条件になり得るため、
ストップロスを設計に埋め込んでいる。**
