あなたは今、GitHub Actions 上で無人実行されています。週次の振り返りの日です。
職務規程（CLAUDE.md）に従ってください。

**今日のあなたの仕事は「記事を書くこと」ではありません。**
今週の観測から1つ判断を下し、それを記録に残すことです。

## 手順

### 1. 停止条件を確認する

`state/health.json` と `state/config.json` を読み、`halted` が true、
または `startedAt` から `experimentDays` 日が経過していれば、
`node scripts/notify.mjs` で総括を報告して終了してください。

### 2. 観測する

`<redirectorBase>/stats.json` を WebFetch します（未セットアップなら飛ばす）。

見るのは3つだけです。

- `totalClicks` の推移
- `byLink` — どの本が押されたか
- `byReferrer` — どの記事から押されたか

### 3. 判断する

`state/config.json` の `operatingVariables` は2つあります。

- `themeStrategy` — テーマの選び方
- `titlePattern` — タイトルの型

**変更するのは1週間に1つまで。2つ同時に動かすと、どちらが効いたか永久に分かりません。**

そして重要な前提です。**この段階のPV数では統計的な有意差は出ません。**
「クリックが3件から5件に増えたから効いた」という判断は、ほぼノイズです。
あなたに期待されているのは、当てることではなく、
**根拠と反証条件を明示して1つ動かし、次回それを確認すること**です。

据え置く判断も正当です。その場合は「なぜ動かさないか」を書いてください。

### 4. 記録する

`state/decisions.jsonl` に**必ず1行追記**します。変えなかった週も追記します。
空白の週があると、後から「動いていなかったのか、判断して据え置いたのか」が区別できません。

```json
{"date":"YYYY-MM-DD","observed":{"totalClicks":0,"byLink":{},"newArticles":7},"hypothesis":"...","change":{"variable":"titlePattern","from":"...","to":"..."},"nextCheck":"来週、○○が△△を上回れば支持、下回れば棄却"}
```

据え置いた週は `"change": null` とし、`hypothesis` に理由を書いてください。

変更した場合は `state/config.json` の該当変数と `changedAt` も更新します。

### 5. 横展開の閾値を確認する

`expansionThreshold` に達していたら、**Slack へ通知するだけ**にしてください。
ジャンルの追加はあなたの仕事ではありません。人間が承認します。実行しないでください。

### 6. note 投稿キットを作る

今週の記事から1本選び、`outbox/note/YYYY-MM-DD.src.md` を作ります。

- frontmatter は `title` のみ
- **要約と導線だけ。全文転載は禁止**（note は canonical を設定できないため、
  全文を出すと本家ブログが検索から消えます）
- アフィリエイトリンクは貼らない。ブログ記事へのURLを1本だけ置く
- **PR表記は必ず入れる**（リンクを貼らなくても、アフィリエイト記事への誘導は規制対象）
- 見出し `#`、強調 `**`、箇条書き `-` のみ。**表・コードブロック・脚注は禁止**
  （note のエディタで崩れます）

書けたら生成します。

```bash
npm run note-kit
```

落ちたら本文を直してください。チェックを緩めることは禁止です。

### 7. 報告する

`node scripts/notify.mjs` で週次サマリを1本送ります。含めるのは以下。

- 今週の記事数、累計クリック数
- 下した判断（変えた／据え置いた、とその理由）
- note 投稿キットのファイル名（人間がこれを開いてボタンを押します）
- 人間の判断が要る事項があればそれ（無ければ「なし」と明記）

**日次の細かい報告は送らないでください。読まれない通知は無いのと同じです。**

## やってはいけないこと

- ジャンルの追加・変更（通知するだけ）
- Amazon アソシエイトの登録判断
- 操作変数を2つ以上同時に変更すること
- note への自動投稿（キットを作るだけ。投稿は人間）
- `scripts/check.mjs` の条件を緩めること
